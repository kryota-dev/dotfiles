# 調査の出典

提供元の URL の一覧は持たない（古くなるため）。出発点は、リポジトリが既に引いている出典とする。
[model-roles.md](../../pr-workflow/references/model-roles.md) と定義ファイルから既存の出典を確かめる。
`git grep -noE 'https?://[^) ]+' -- <役割表の文書と構成の文書>` でも拾える。
URL にモデルの名前が入っていれば新モデルの版に読み替え、無ければ提供元の文書の索引から探す。発表のページは読み替えが当たらないことがあるので、検索で探す。見つからなければ「無い」と書く。

## 一次ソースの種類

| 種類 | 読み取ること | 使いみち |
|---|---|---|
| 発表（ニュース・ブログ） | 公開日、位置づけ、提供元の自己申告の評価 | 公開の事実。数値は自己申告として扱う |
| モデルの一覧・モデルのページ | ID（エイリアスと固定の ID）、コンテキスト、最大出力、知識のカットオフ、effort の段と既定 | 定義とハーネスの既定に書く値 |
| 料金 | 入出力の単価、長い入力の扱い、キャッシュ | 段の位置づけ（同じ段に並ぶか） |
| プロンプトのガイド（モデルごと、または最新モデル向け） | 傾向と、提供元が勧める対策 | 役割の本文と「弱点への対策」 |
| 移行のガイド・新機能 | API の引数や既定の変化、壊れる変更 | ハーネスの設定への影響 |
| System Card・安全性の資料 | 安全の分類器、拒否、fallback の挙動 | fallback の記述 |
| 廃止予定 | 旧モデルの期日 | 据え置けるか、いつまでか |
| ハーネスの側 | モデルの設定のページ、CLI のリリースノート、プランごとの提供、非対話の実行での課金や同意、手元のカタログ（書いた時点の例: Codex の `~/.codex/models_cache.json`） | 手元で使えるか、既定が変わったか |

## 提供元ごとの当てはめ

- **Anthropic**: モデルの概要、モデルごとのプロンプトのガイドと新機能のページ、料金、System Card、モデルの廃止予定、Claude Code のモデルの設定（model-config）とリリースノートを読む。プロンプトのガイドはモデルごとに別のページになっている。
- **OpenAI**: モデルのページ、料金、最新モデルのガイド（プロンプトの書き方と移行）、廃止予定、System Card、Codex のモデルのページと CLI のリリースノートを読む。最新モデルのガイドは URL が「最新」を指し、中身が入れ替わる。
- **そのほかの提供元**: 同じ種類を当てはめ、無い種類は「無い」と書く。先に手元のハーネスから呼ぶ経路があるかを確かめる。

## 第三者の評価と利用者の声

- 独立のベンチマーク、自社の用途で実測した企業の記事、報道、開発者のフォーラム、実地テストの記事を読む。
- 自己申告／第三者の測定／利用者の声を分けて書く。同じ指標で食い違う数値は、出典と一緒に並べる（評価の違いを残すため）。
- 数値は、指標の名前・版・測った effort と一緒に書く（名前の似た別の指標を取り違えるため）。
- 検索や取得の道具が返す要約の数値は使わず、ページの本文で確かめる。要約は、本文に無い値を混ぜることがある。
- 公開から日が浅い評判は、何日分かを書く。
- 測った条件（ハーネス・effort）が手元と同じかを確かめ、違えばその旨を書く（手元での評価と混同しないため）。

## 読めなかったページ

読めなかったページは、読めなかったと比較に書く。その内容を別の記事から引いたら、孫引きと書く。

## 新しい ID の試走

短い依頼を 1 回だけ送り、動くことを確かめる。effort は、そのモデルを使う役割と同じ値にする。次の起動形は、どちらも実機で 1 回ずつ確かめてある。

- GPT: `codex exec --sandbox read-only -m <新しい ID> -c model_reasoning_effort="<役割の effort>"` に短い依頼を stdin で渡す（起動形は [codex skill](../../codex/SKILL.md)）。終了コードが 0 で、ログの `model:` の行が `<新しい ID>` であることを見る。手元の設定についての警告は、ID が使えるかどうかとは別に扱う。
- Claude: 次の形で起動する。結果の `modelUsage` に `<新しい ID>` があり、出力トークンが 0 でないことを見る。補助の小さいモデルが一緒に並ぶことがあるので、「ほかのモデルが無いこと」では判定しない。

```bash
echo "1 行で答える: 2+3 は？" | claude -p --model "<新しい ID>" --effort "<役割の effort>" --output-format json \
  --setting-sources "" --strict-mcp-config --tools "" > "$OUT" 2> "$OUT.err"
jq '.modelUsage | map_values({inputTokens, outputTokens})' "$OUT"
```

- 据え置きが選択肢に入るなら、旧 ID でも同じ形で 1 回動かし、旧 ID が載ることを見る（ハーネスが旧 ID を黙って新しい版に読み替えていないかを確かめるため）。
- 動かなければ、CLI の更新が要るのか、プランで未提供なのかを切り分けて書く。CLI の更新が要るなら、比較に書く。
- T3 Code などの別のハーネスが新しい ID を扱えるかは、確かめられなければ、比較の「未確認のこと」に載せる。
