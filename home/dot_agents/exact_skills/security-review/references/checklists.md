# セキュリティレビュー — フェーズ別チェックリストとプロンプトテンプレート

各フェーズで Claude と GPT の leg に渡すプロンプトのテンプレートと、検査項目の詳細。
`[攻撃面マップ]` のプレースホルダは Phase 1 の出力で置き換える。

## プロンプト設計の原則

### Claude 向け（Phase 2 の `review-security`・`review-security-deep`）

自律性が高い。ロールと目的を冒頭で簡潔に定義し、手順を逐一規定しない。
検査項目はカテゴリとして渡して委ねる。出力形式は構造だけ指定する。見る範囲（攻撃面マップの箇所）と完了の条件を書き、
「念のため再確認する」のような検証の指示は足さない。考える量は役割の effort で決まる（モデルの性質と対策は model-roles.md）。
攻撃面マップに貼るコードや設定の抜粋は `<pasted_content id="<乱数>">` で囲む。

### GPT 向け（Phase 2 の `reviewer-gpt`、Phase 3-4）

Goal / Context / Constraints / Done when の 4 部構成に従う（`codex` skill）。Constraints に見る範囲を、Done when に出力の形を書く。
Phase 2 のテンプレートは Claude と同じ内容を渡し、末尾の「完了の条件」を Done when として扱わせる。

## Phase 2 プロンプトテンプレート（Claude と GPT の両方に渡す）

```
このプロジェクトのソースコードのセキュリティレビュアーとして、
以下の攻撃面マップをもとに脆弱性を探せ。

[攻撃面マップ]

以下のカテゴリを網羅すること。

入力検証: インジェクション（SQL / NoSQL / コマンド / テンプレート）、
パストラバーサル、XSS、SSRF、ReDoS。

認証・認可: トークン検証の不備、セッション固定、認可チェックの欠落（IDOR）、
権限昇格、アクセス制御ルールのロジック不備、RBAC/ABAC の実装と定義の乖離、
トークンの有効期限・失効処理。

暗号・シークレット: ハードコードされた秘密情報、弱い暗号アルゴリズム、
不適切な乱数生成。

データ保護: PII の不適切な露出、機密データの平文保存、
クライアントサイドストレージへの機密情報の保存、CORS の過剰許可。

ビジネスロジック: レースコンディション（TOCTOU）、冪等性の欠如、
数値のオーバーフロー・丸め誤差、状態遷移の不正な経路。

依存関係: 既知の脆弱性を持つパッケージ、lockfile の整合性、
postinstall スクリプトのリスク。

各発見を以下の形式で出力:
- ファイル:行番号
- 脆弱性の種類（CWE 番号があれば付記）
- 深刻度: Critical / High / Medium / Low / Info
- 概要（1 文）
- 再現シナリオ
- 修正案
- 検証方法

再現シナリオは、脆弱な経路（入力から問題の箇所まで）を示すにとどめる。exploit のコードは書かない。
確信が持てない主張には「（未確認）」と付ける。
完了の条件: 上の全カテゴリを、攻撃面マップの範囲で確認した。該当が無いカテゴリは「該当なし」と書いた。
条件を満たしたら止まる。範囲の外のコードは、経路を追うのに必要なときだけ読む。
```

## Phase 3 プロンプトテンプレート（GPT: `reviewer-gpt`）

```
## Goal
STRIDE フレームワークで脅威を列挙し、
各脅威に攻撃経路・影響・緩和策・残余リスクを提示する。

## Context
このプロジェクトの攻撃面マップ:

[攻撃面マップ]

## 各脅威について以下を記述

1. 脅威の名前と STRIDE カテゴリ
2. 攻撃者のプロファイル: 動機、能力、アクセスレベル
3. 攻撃経路: 目的達成までのステップ（具体的に）
4. 前提条件: 攻撃が成立するために必要な条件
5. 影響: 成功した場合のビジネスインパクト
6. 既存の緩和策: コードや設計で既に対策されている点
7. 残余リスク: 緩和策では防げない部分
8. 追加対策の提案（優先度付き）

特に注意する攻撃パターン:
- 認可の境界を超えるデータアクセス
- オフライン / キャッシュの操作による整合性破壊
- クライアントサイドの改ざん（DevTools / プロキシ経由）
- サプライチェーン攻撃（依存パッケージ、CI/CD）
- ソーシャルエンジニアリング（招待・共有リンクの悪用）
- タイミング攻撃（レースコンディションの悪用）

## Constraints
- 確認や質問は不要
- 確信が持てない技術的主張には「（未確認）」と明示する
- コードを変更しない

## Done when
全 STRIDE カテゴリ（Spoofing / Tampering / Repudiation /
Information Disclosure / Denial of Service / Elevation of Privilege）を
網羅し、各脅威に攻撃経路・影響・緩和策・残余リスクを記述した。
```

## Phase 4 プロンプトテンプレート（GPT: `checker-gpt`）

```
## Goal
デプロイ設定・インフラ設定のセキュリティ不備を検出する。

## Context
このプロジェクトの攻撃面マップ（デプロイ・インフラ部分）:

[攻撃面マップから、デプロイ先・CI/CD・クラウドサービスの情報を抜粋]

## 検査項目

HTTP セキュリティヘッダ:
Content-Security-Policy、Strict-Transport-Security、
X-Content-Type-Options、X-Frame-Options / frame-ancestors、
Referrer-Policy、Permissions-Policy。

CORS 設定:
Access-Control-Allow-Origin の範囲、credentials の許可範囲。

デプロイ設定:
本番ビルドにデバッグ情報が含まれていないか、
Source map が公開されていないか、
環境変数の漏洩（クライアントバンドルへの混入）、
CI/CD パイプラインのシークレット管理。

クラウドサービスの設定:
IAM / サービスアカウントの権限（最小権限の原則）、
ストレージのアクセス制御、ログ・監視の設定、
バックアップと災害復旧。

暗号化:
転送中の暗号化（TLS バージョン、証明書）、保存時の暗号化。

## Constraints
- 確認や質問は不要
- 確信が持てない技術的主張には「（未確認）」と明示する
- コードを変更しない
- 各不備に具体的な修正案を付ける

## Done when
全検査項目を確認し、不備のある項目について具体的な修正案を記述した。
不備が無い項目は「問題なし」と明示した。
```

```markdown
## 発見事項一覧（深刻度順）

| # | 深刻度 | 種類 | 概要 | ファイル | 対応状況 |
|---|---|---|---|---|---|

## Critical / High の詳細

（各発見の再現シナリオ、修正案、検証方法）

## 脅威モデル概要

（STRIDE の結果から、残余リスクが高いものを抽出）

## 設定レビューの結果

（不備がある項目のみ）

## 推奨アクション（優先度順）

1. 即時対応（Critical / High）
2. 短期対応（Medium、次リリースまで）
3. 中期対応（Low / Info、ロードマップに載せる）

## 対象外・制約事項

（今回のレビューでカバーできなかった領域）
```
