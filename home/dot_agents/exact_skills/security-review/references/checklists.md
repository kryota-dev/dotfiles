# セキュリティレビュー — フェーズ別チェックリストとプロンプトテンプレート

各フェーズで subagent / Codex に渡すプロンプトのテンプレートと、検査項目の詳細。
`[攻撃面マップ]` のプレースホルダは Phase 1 の出力で置き換える。

## Phase 2 プロンプトテンプレート（Fable 5.1 subagent）

```
あなたは、このプロジェクトのソースコードに対するセキュリティレビュアーである。
以下の「攻撃面マップ」をもとに、ソースコードを精査せよ。

[攻撃面マップ]

## 検査項目

### 入力検証とサニタイズ
- ユーザー入力がサニタイズなしで使われている箇所
- SQL / NoSQL / コマンドインジェクション
- パストラバーサル
- XSS（Stored / Reflected / DOM-based）
- SSRF（内部ネットワークへのリクエスト偽造）
- テンプレートインジェクション
- 正規表現 DoS（ReDoS）

### 認証・認可
- 認証バイパスの可能性（トークン検証の不備、セッション固定）
- 認可チェックの欠落（IDOR、権限昇格）
- アクセス制御ルール（Security Rules / ポリシーファイル）のロジック不備
- RBAC / ABAC の実装と定義の乖離
- トークンの有効期限・失効処理

### 暗号・シークレット
- ハードコードされたシークレット / API キー / パスワード
- 弱い暗号アルゴリズムの使用
- 不適切な乱数生成（Math.random を認証に使用等）

### データ保護
- PII の不適切な露出（ログ、エラーメッセージ、API レスポンス）
- 機密データの平文保存
- クライアントサイドストレージへの機密情報の保存
- CORS の過剰許可

### ビジネスロジック
- レースコンディション（TOCTOU）
- 冪等性の欠如による二重処理
- 数値のオーバーフロー / 丸め誤差（金額計算）
- 状態遷移の不正な経路

### 依存関係
- 既知の脆弱性を持つ依存パッケージ
- lockfile の整合性
- postinstall スクリプトのリスク

## 出力形式（各発見について）

- **ファイル:行番号**
- **脆弱性の種類**（CWE 番号があれば付記）
- **深刻度**: Critical / High / Medium / Low / Info
- **概要**: 何が問題か（1 文）
- **再現シナリオ**: どういう入力・状態で問題が顕在化するか
- **修正案**: 具体的なコード変更の方針
- **検証方法**: 修正後に何を確かめれば安全と言えるか
```

## Phase 3 プロンプトテンプレート（Codex GPT-5.4）

```
このプロジェクトの脅威モデリングを実施せよ。
以下の「攻撃面マップ」とソースコードの構造をもとに、STRIDE フレームワークで脅威を列挙する。

[攻撃面マップ]

## 各脅威について

1. **脅威の名前と STRIDE カテゴリ**
2. **攻撃者のプロファイル**: 動機、能力、アクセスレベル
3. **攻撃経路**: 攻撃者が目的を達成するまでのステップ（具体的に）
4. **前提条件**: 攻撃が成立するために必要な条件
5. **影響**: 成功した場合のビジネスインパクト
6. **既存の緩和策**: コードや設計で既に対策されている点
7. **残余リスク**: 緩和策では防げない部分
8. **追加対策の提案**: 優先度付き

## 特に注意する攻撃パターン
- 認可の境界を超えるデータアクセス
- オフライン / キャッシュの操作による整合性破壊
- クライアントサイドの改ざん（DevTools / プロキシ経由）
- サプライチェーン攻撃（依存パッケージ、CI/CD）
- ソーシャルエンジニアリング（招待・共有リンクの悪用）
- タイミング攻撃（レースコンディションの悪用）

確認や質問は不要。確信が持てない技術的主張には「（未確認）」と明示する。
```

## Phase 4 プロンプトテンプレート（Codex GPT-5.4）

```
このプロジェクトのデプロイ設定・インフラ設定のセキュリティを検証せよ。

## 検査項目

### HTTP セキュリティヘッダ
- Content-Security-Policy の有無と妥当性
- Strict-Transport-Security
- X-Content-Type-Options
- X-Frame-Options / frame-ancestors
- Referrer-Policy
- Permissions-Policy

### CORS 設定
- Access-Control-Allow-Origin の範囲
- credentials の許可範囲

### デプロイ設定
- 本番ビルドにデバッグ情報が含まれていないか
- Source map が公開されていないか
- 環境変数の漏洩（クライアントバンドルへの混入）
- CI/CD パイプラインのシークレット管理

### クラウドサービスの設定
- IAM / サービスアカウントの権限（最小権限の原則）
- ストレージのアクセス制御（公開バケット等）
- ログ・監視の設定
- バックアップと災害復旧

### 暗号化
- 転送中の暗号化（TLS バージョン、証明書）
- 保存時の暗号化

確認や質問は不要。確信が持てない技術的主張には「（未確認）」と明示する。
```
