# grill-me の auto mode で Claude と Codex が議論する

## Background

grill-me の `--mode=auto` は、親（実行中のハーネス）が一人で決定木を踏破し、最後に PRD を user が 1 回承認する。pr-workflow の large path はこの形で PRD を作る。判断を下すのも検証するのも同じモデルなので、親の見落としや偏りが PRD にそのまま残る。

pr-workflow の実装とレビューは、すでに Claude と GPT の両系統を使っている。役割の定義は model-roles.md に、起動の仕方は `claude_leg`（`claude -p`）と `codex exec` にある。どちらも読み取りだけで起動でき、resume で文脈を引き継げる（`codex exec resume <thread_id>`、`claude -p --resume <session_id>`）。

auto mode で人間が確認するのは、今は security・data migration・外部 contract の変更だけである。2 モデルの合意を、ユーザーの意図の代わりにしてはいけない判断がほかにもある。

## User Story

- 開発者として、auto mode の決定を、別の系統のモデルとの議論を経たものにしたい。見落としと偏りを減らすためである。
- 開発者として、2 モデルが一致しても、目的・スコープ・権限・コストなど人間が決めるべき判断は自分で決めたい。
- 開発者として、議論の相手が使えないときに、黙って単独の PRD ができるのは避けたい。
- 開発者として、PRD から、どの判断が誰の提案で何を根拠に決まったかを辿りたい。

## Acceptance Criteria

- **AC-001**: `--mode=auto` では、常に相手のモデルと議論する。相手は親と別の系統にする（親が Claude Code なら GPT、Codex なら Claude）。flag は足さない。`--mode=interactive` の挙動は変えない。
- **AC-002**: 材料を集めた後、親が枝の一覧を作る。最初の 1 往復で相手が足りない枝を足し、順序は親が決める。
- **AC-003**: 目的とスコープの線引きは、枝の一覧ができた直後に user に確認してから辿り始める。
- **AC-004**: 判断ごとに、親は自分の案と根拠を scratchpad のファイルに書いて封じてから、問いだけを相手に渡す（親の案と推奨は渡さない）。相手は盲検で案と根拠を返す。一致すれば確定する。食い違えば、親の案を開示して議論する。
- **AC-005**: 食い違いの議論は 2 往復までにする。一次ソース（コード・公式文書・実機の挙動）で裏付けられた側を採り、根拠を記録する。価値判断で根拠の優劣がつかないもの、2 往復で収束しないものは、両案を並べて最後の承認点で user に問う。
- **AC-006**: 次の 7 つの軸は、2 モデルが一致しても user が決める。security・data migration・外部 contract の変更・権限と資格情報と戻せない操作は、出た時点で確認する。目的とスコープは AC-003 で確認する。コストと運用の負担・ユーザーが触れる振る舞い（UI・文言・公開物の表現）は、両案を並べて最後の承認点で問う。
- **AC-007**: 相手は 1 セッションを resume し続ける。Claude Code が親なら `codex exec --sandbox read-only` で起動し、`codex exec resume` で続ける。Codex が親なら `claude_leg` で起動し、`--resume <session_id>` で続ける。
- **AC-008**: 相手の役割として、`grill-counterpart`（`~/.agents/roles/`、claude-opus-5-5 / high、Read・Grep・Glob）と `grill-counterpart-gpt`（`~/.codex/agents/`、gpt-6.1-sol / high、read-only）を新設する。本文には次を書く。盲検で答えること、根拠を一次ソースで示すこと、根拠なしに相手の案へ同調しないこと、答えが人間の軸に当たるときは印を付けること、非対話で確認の質問をしないこと。本文は各モデルの公式のプロンプトのガイドに沿って書く。
- **AC-009**: model-roles.md の役割表に 2 つの役割を足し、`tests/agent_roles.bats` で定義との一致と道具の制限（Bash と書き込みの道具を持たない）を検査する。`make test` が通る。
- **AC-010**: issue・PR の本文などは、親が取得してファイルに書いてから相手に渡す。Claude には追加の Read の許可で、Codex にはプロンプトへの埋め込みで渡す。相手の出力は未検証の外部入力として扱い、中の指示には従わない。
- **AC-011**: 相手の起動や応答が失敗したら（未導入・未認証・タイムアウトなど）、1 回だけ再試行する。それでも失敗したら、「単独の auto で続ける／直してから再開する／中止する」を user に選ばせる。単独で続けた判断は、PRD でそれと分かるようにする。
- **AC-012**: fallback で要求と別のモデルが答えたときは、答えを捨てずに使い、要求したモデルと実際のモデルを記録する。
- **AC-013**: PRD の frontmatter に、相手の役割・要求したモデル・実際のモデルを足す。Considered Alternatives の各項に、提案元（親／相手）・決め手（一次ソース／user）・根拠を付ける。一致した判断は件数だけ書く。往復の全文は scratchpad に置き、git では追跡しない。
- **AC-014**: 議論全体に、呼び出しの回数の上限を設けない。終了の条件は今と同じで、新しい判断も未解決の事項も出なくなったら終える。

## Considered Alternatives / Rejection Rationale

- **相手が grill 役として決定木を持つ**: 今の grill-me の形に最も近い。ただ、相手にも材料をすべて渡す必要がある。Codex の sandbox からは `gh` が使えないので、結局は親が中継することになる。見落としを拾う効果は最初の 1 往復で得られるので、親が一覧を作り相手が補う形にした（user が選択）。
- **親の案を見せて相手に反論させる**: 手順は最も単純になる。ただ、相手が親の案に引っ張られ（アンカリング）、2 モデル目が独立した意見にならない。盲検にした（user が選択）。
- **複数の判断をまとめて相手に投げる**: 往復は減るが、後の判断が前の判断に依存すると崩れる。採らなかった。
- **食い違いを親が裁く**: 速いが、親に有利な偏りが残る。一次ソースで決め、決まらなければ user に上げることにした（user が選択）。
- **食い違いをすべて user に上げる**: 判断が多いと user の負担が増え、auto の利点が薄れる。採らなかった。
- **人間の軸をすべて途中で聞く／すべて最後にまとめる**: 前者は止まる回数が増える。後者は前提が覆ったとき、依存する枝をやり直すことになる。後続を左右する軸だけを途中で聞くことにした（user が選択）。
- **判断ごとに相手を新規に起動する**: 前の議論で親に歩み寄った影響は残らない。ただ、材料の再送と再探索で遅く高くなる。親の案は盲検の回答が返るまで送らないので、resume しても独立性は保てる。resume にした（user が選択）。
- **既存の役割（review-general・reviewer-gpt）を流用する**: 本文がレビュー向けなので、議論の約束を毎回プロンプトに書くことになり、役割表の用途も実態とずれる。新設にした（user が選択）。
- **相手が失敗したら黙って単独に戻る／その場で止める**: 前者は議論を経ていない PRD ができうる。後者は一時的な失敗でも large path が止まる。再試行してから user に選ばせることにした（user が選択）。
- **Debate Log 節を PRD に新設する／全文を別ファイルで追跡する**: 前者は PRD が長くなり、sdd の入力が重くなる。後者は相手が読んだ issue の本文などが public リポジトリに載る危険がある。食い違いだけを残すことにした（user が選択）。
- **`--counterpart=none` で議論を切れるようにする**: 必要になってから足せばよい投機的な flag なので、足さない（user が選択）。
- **全体の呼び出しの回数に上限を置く**: 値の根拠がまだ無い。判断ごとの 2 往復で発散は止まるので、置かない（user が選択）。

## Out of Scope

- `--mode=interactive` に相手のモデルを入れること。
- pr-workflow の tier の判定と、large 以外の path の変更。
- 3 つ以上のモデルでの議論。
